# 旺店通库存、运营与采购日报系统——业务与管理交接文档

> 文档版本：1.0
> 交接基准日期：2026-09-02
> 适用对象：运营、采购、仓储、财务、管理人员、项目负责人

---

## 1. 这套系统是做什么的

这套系统把旺店通里的商品、仓库、库存、销售、退货和出入库数据每天同步下来，然后自动整理成网页看板和 Excel 报表，帮助团队回答以下问题：

- 每个仓库现在有多少库存？
- 哪些商品没有可用库存或即将缺货？
- 哪些商品库存过多、卖得慢、可能需要清仓？
- 最近哪些 SKU 卖得快、退货多或趋势下降？
- 哪些 SKU 需要采购，什么时候下单，建议下多少？
- 哪些仓库之间可以优先调拨，而不是直接采购？
- 各店铺、各仓库、各商品简称的销售表现如何？
- 每天的同步有没有成功？

这套系统是一个“经营和供应链决策辅助工具”，不是旺店通本身，也不会自动替采购人员下单。

## 3. 系统每天怎么工作

正常情况下，每天凌晨 01:10 自动执行：

1. 同步前一天的销售出库；
2. 同步前一天的退货入库；
3. 同步取消订单；
4. 同步出入库流水；
5. 更新商品和供应商资料；
6. 刷新当前库存和采购在途；
7. 记录同步结果；
8. 生成前一天的 Excel 日报。

例如：

- 2026-09-02 凌晨执行；
- 正常处理的业务日期是 2026-09-01；
- 日报也应是截至 2026-09-01 的数据。

网页是否一直打开，不影响凌晨任务。网页和每日同步是两个独立程序。

## 5. 网页各页面怎么理解

### 5.1 数据看板

用于快速看整体情况，包括：

- 当前库存件数；
- 可用库存；
- 采购在途；
- 库存金额；
- 销售和退货；
- 净销量；
- 无可用库存数量；
- 销量趋势和仓库概览。

建议管理人员每天先看这一页，再进入具体预警。

### 5.2 库存明细

按 SKU 查看：

- 当前库存；
- 可用库存；
- 分布仓库；
- 销售、退货和采购入库；
- 预计可售天数。

“当前库存”和“可用库存”不是同一个概念：

- 当前库存：账面上实际存在的库存；
- 可用库存：扣除占用、冻结等因素后可继续销售或分配的库存。

采购和调拨判断更应关注可用库存。

### 5.3 入库分析

用于查看一段时间内的：

- 总入库；
- 采购入库；
- 调拨入库；
- 退货入库；
- 其他入库；
- 入库 SKU 数量。

这页适合仓储和采购核对“货是否真正入库”。

### 5.4 仓库销量与退货

以“仓库 + SKU”为单位，查看：

- 销售出库；
- 退货入库；
- 净销量；
- 7 日、15 日、30 日表现。

“净销量”一般理解为销售出库减去退货，但实际金额和数量仍要结合页面字段和旺店通单据核对。

### 5.5 分店铺统计

以“店铺 + SKU”为单位查看销售情况，适合分析：

- 哪个店铺贡献销量；
- 同一 SKU 在不同店铺的表现；
- 店铺退货和净销量；
- 店铺销售金额。

历史店铺数据如果曾经缺失，需要技术人员执行补录程序后才完整。

### 5.6 简称汇总

把多个规格或 SKU 按商品简称汇总，适合运营从“产品系列”角度看销量，而不是只看单个规格。

### 5.7 库存预警

用于识别：

- 即将缺货；
- 库存偏高；
- 中度积压；
- 严重积压；
- 清仓预警。

预警只是系统计算结果，不应脱离以下信息直接处理：

- 是否有活动计划；
- 是否有大客户订单；
- 是否有旺季或淡季；
- 是否有在途未入库；
- 是否正在切换新老款；
- 商品资料是否完整。

### 5.8 采购计划

采购计划回答三个问题：

1. 是否需要关注；
2. 建议什么时候下单；
3. 建议下多少。

采购计划目前只覆盖五个运营仓：

- 主仓库（新）
- TMT康复仓
- 杰菲克德国仓
- 日本仓
- ENYISA仓

清仓款不会进入正常采购计划。

### 5.9 调拨建议

当某个仓库缺货风险较高，而另一个仓库有可调拨库存时，系统给出仓间调拨建议。

实际执行前仍需确认：

- 来源仓调出后是否安全；
- 目标仓多久会缺货；
- 运输需要几天；
- 运费和采购成本；
- 是否有在途采购即将到货。

### 5.10 清仓汇总

用于查看清仓款的：

- SKU 数量；
- 涉及仓库；
- 库存件数；
- 可用库存；
- 采购成本；
- 缺少采购价的数据。

如果采购价缺失，清仓资金占用会不准确，应优先补齐商品资料。

## 6. 采购计划怎么计算

本节用业务语言解释当前规则。更精确的公式以 `docs/purchase-planning-rules.md` 为准。

### 6.1 先估算每天能卖多少

系统主要参考最近 7 天和最近 30 天：

```text
预测日销量 = 近7日日均销量 × 40% + 近30日日均销量 × 60%
```

这样做是为了同时考虑近期变化和较长期的稳定水平。

需要注意：如果某几天因为缺货没有销量，系统目前可能把这几天当成真正的零销量，因此会低估需求。这是已知需要继续优化的问题。

### 6.2 再判断库存还能卖几天

```text
可供使用的数量 = 可用库存 + 采购在途
库存覆盖天数 = 可供使用的数量 ÷ 预测日销量
```

覆盖天数越短，缺货越紧急。

### 6.3 采购数量使用近 7 日周销量

把近 7 日销量总量记作 A：

| 生产周期 | 采购目标库存参考 |
| ---: | ---: |
| 15–20 天 | 4A |
| 25 天 | 7A |
| 30 天左右 | 8A |

再根据销量趋势乘一个倍率：

- 明显下降：减少采购；
- 平稳：按原目标；
- 上涨：适度增加；
- 爆发增长：进一步增加。

当前正在整理中的新规则是：采购数量以目标库存为基础，不再直接扣减可用库存、在途和建议调拨；这些数据主要用于判断何时缺货和什么时候下单。

由于这项规则对采购金额影响较大，正式使用前必须由采购负责人确认当前服务器是否已经发布了这一版本。

### 6.4 最低起订量

- SKU 有起订量：按 SKU 配置；
- 没有配置：默认 100 件；
- 明确写“无”：不强制 100 件；
- 计算量低于起订量：会补到起订量。

### 6.5 50 件取整

达到起订量后，系统按 50 件倍数调整：

| 原计算量 | 建议量 |
| ---: | ---: |
| 103 | 100 |
| 109 | 100 |
| 111 | 150 |
| 238 | 250 |

### 6.6 固定下单日

当前整理中的规则：

- 宏博、铠博以及历史名称“博凯”的基础款：每月 5 日、20 日作为执行参考；
- 其他供应商基础款：每周四下单；
- 放大款、测款：按库存天数触发；
- 如果已经进入紧急缺货期，不应为了等固定日期而延迟下单。

### 6.7 低销量观察

当一个 SKU：

- 最近 30 天有销量；
- 最近趋势明显下降；
- 预测每天销量不到 1 件；

系统会标记为低销量观察/清仓候选，建议采购量设为 0，避免因为默认起订量再次大量采购。

## 7. Excel 日报怎么使用

日报和周报共有 11 个工作表：

1. 日报总览
2. 清仓预警
3. 库存积压预警
4. 采购在途预警
5. 结构调整建议
6. 零销量与新品
7. 采购计划
8. 供应商分析
9. 在途与入库
10. 同步日志
11. 计算口径

### 7.1 建议阅读顺序

管理人员：

1. 日报总览；
2. 库存积压预警；
3. 采购计划；
4. 同步日志。

采购人员：

1. 采购计划；
2. 供应商分析；
3. 采购在途预警；
4. 在途与入库；
5. 计算口径。

运营人员：

1. 清仓预警；
2. 库存积压预警；
3. 结构调整建议；
4. 零销量与新品。

### 7.2 采购计划颜色

- 红色：交期内可能缺货，需要优先处理；
- 黄色：未来 7 天内建议下单；
- 蓝色：7 天以后计划下单；
- 紫色：低销量观察/清仓候选，建议量为 0；
- 无颜色：生产周期等资料缺失，系统暂时无法计算。

### 7.3 报表不是订单

报表中的“建议下单量”不是已经创建的采购单。正式下单前采购人员必须核对：

- 旺店通实时库存；
- 已下单但系统中未体现的采购；
- 供应商交期；
- 活动和销售计划；
- 起订量和包装规格；
- 调拨可能性；
- 商品是否准备清仓或换代。

## 8. 每日使用流程

### 8.1 运营/采购每天上午检查

1. 打开网页；
2. 确认页面显示“正式环境”，不是演示模式；
3. 确认最后同步日期是昨天；
4. 打开日报总览；
5. 先看红色缺货风险；
6. 再看黄色一周内采购计划；
7. 检查紫色低销量候选；
8. 检查采购在途和入库；
9. 对异常 SKU 回到旺店通核对；
10. 将确认后的采购或调拨动作记录到业务流程中。

### 8.2 如果最后同步日期不是昨天

不要直接使用采购建议做决定，应立即通知技术人员，并提供：

- 当前看到的最后同步日期；
- 页面地址和端口；
- 是否能正常打开其他页面；
- 是否显示错误提示；
- 截图中不要包含密钥。

### 8.3 如果某个 SKU 数量明显不对

先确认：

1. 是否选错仓库；
2. 是否看的是本机旧数据；
3. 旺店通当前库存是多少；
4. 是否存在占用、冻结或在途；
5. 商品编码是否一致；
6. 是否有退货或取消单还未同步；
7. 最后同步是否成功。

然后将以下信息交给技术人员：

- SKU 编码；
- 仓库名称；
- 业务日期；
- 系统显示值；
- 旺店通显示值；
- 相关订单号或单据号。

## 9. 哪些数据可以相信，哪些要特别核对

### 9.1 可以作为日常参考

在同步成功、日期正确的前提下，可以参考：

- 当前库存和可用库存；
- 仓库维度销售和退货；
- 店铺维度销售；
- 采购在途；
- 缺货和积压预警；
- 建议下单日期和建议量；
- 清仓库存和成本汇总。

### 9.2 必须人工复核

以下情况不能只依赖系统：

- 大促、直播、临时大单；
- 新品刚上线、历史销量不足；
- 商品长期缺货；
- 商品即将换代或停产；
- 供应商临时延期；
- 采购单已下但旺店通在途未及时更新；
- 跨境仓运输时间变化；
- 商品资料缺少生产周期、采购价或起订量；
- 需要大额采购或清仓处理。

## 10. 常见问题

### 10.1 页面打不开

先确认：

- 当前是否在公司网络或已连接服务器；
- 地址和端口是否正确；
- 其他同事是否也打不开。

然后联系技术人员，不要反复刷新或自行重启服务器。

### 10.2 页面能打开，但数据很旧

最常见原因：

- 每日任务失败；
- 打开了本机旧环境；
- 网络中断；
- 旺店通接口限频；
- 服务器磁盘或数据库异常。

在恢复前，暂停使用系统采购建议。

### 10.3 日报没有生成

可能是同步失败，也可能是旧定时任务只同步数据、不生成 Excel。请技术人员检查任务是否使用 `--daily-job`。

### 10.4 报表下载很慢

数据库较大，日报可能超过 1 MB，生成时要查询很多明细。不要连续多次点击下载。必要时让技术人员在服务器后台生成后直接发送文件。

### 10.5 某行没有颜色也没有建议量

通常说明缺少：

- 生产周期；
- 商品结构；
- 供应商；
- 销量历史；
- 起订量等关键资料。

应先补商品资料，而不是手工猜测系统公式。

### 10.6 红色是否一定要马上采购

红色表示按照当前数据和交期，存在较高缺货风险。处理方式可以是：

- 立即采购；
- 加急生产；
- 仓间调拨；
- 调整活动和销售节奏；
- 核对是否有未同步在途；
- 确认是否本来就准备清仓。

红色代表“优先核对和决策”，不等于自动下单。

## 面向业务人员和二开程序的数据 API

项目另外提供了一个只读数据接口。它不是网页，主要给业务人员查询或给其他程序做二次开发：

- 技术人员启动后可打开 `/docs` 查看接口说明；
- 主要入口是 `POST /api/v1/query`；
- 可以按商品、仓库、SKU、店铺、日期等条件筛选；
- 可以按不同粒度分组统计，例如“仓库 + SKU”或“仓库 + 店铺”；
- API 只读，不会改变库存，也不会影响每天的数据同步；
- 按当前要求不设置登录，公网地址上的公开字段任何人都能读取，所以发布前必须确认数据可以公开。

详细使用方法见 [数据库只读 FastAPI 服务说明](数据库只读%20FastAPI%20服务说明.md)。网页端口 5052 和数据 API 端口 8000 是两套用途不同的服务，不要混用。

## 11. 数据和账号安全

### 11.1 不得外传的内容

- 旺店通 SID；
- App Key；
- App Secret；
- 服务器账号和私钥；
- 正式数据库；
- 包含业务明细的报表；
- 客户订单和退款数据。

### 11.2 网页访问限制

当前网页没有账号密码。正确做法是：

- 仅在内网访问；
- 或通过 SSH 隧道/公司 VPN；
- 或由技术人员加反向代理、HTTPS 和登录认证。

禁止把 5052 端口直接开放给公网。

### 11.3 报表发送

日报中可能含库存成本、供应商和经营数据。发送前应：

- 确认收件人；
- 使用公司批准的存储或沟通工具；
- 不上传公共网盘；
- 不发送到私人邮箱；
- 离职交接时收回访问权限。

## 12. 业务负责人需要确认的规则

以下规则不是纯技术问题，必须由业务负责人最终确认：

- 五个采购仓是否仍然正确；
- 哪些仓库可以作为调拨来源；
- 清仓款的定义；
- 商品结构字段的维护方式；
- 默认起订量是否继续使用 100；
- 采购按 50 件倍数取整是否适用于全部供应商；
- 宏博/铠博固定下单日是否确定为每月 5 日和 20 日；
- 其他基础款是否统一每周四下单；
- 采购数量是否不扣减现有库存和在途；
- 低销量候选是否自动建议 0；
- 预警阈值和积压天数是否符合当前经营阶段。

如果规则改变，必须同时通知技术人员修改代码、测试和报表说明，不能只在微信群里口头变更。

## 13. 管理层应关注的主要风险

### 风险一：数据环境混淆

当前本机和服务器存在两份不同新旧程度的数据，端口也可能被转发。操作人员如果选错环境，可能根据旧数据做采购决策。

建议：统一正式访问地址，并在页面明显显示“服务器/本机、数据库日期”。

### 风险二：没有登录认证

任何能访问端口的人都可能查看经营数据或触发同步。

建议：尽快增加登录、HTTPS 和访问白名单。

### 风险三：本机自动任务不正常

本机 daily 任务目前未加载，而且旧配置可能只同步、不生成日报。

建议：明确到底以 Linux 服务器还是本机为唯一生产任务，不要两边同时跑。

### 风险四：采购算法仍在调整

采购数量和固定下单日有未正式提交的修改。业务和技术必须确认服务器实际运行的是哪一版算法。

建议：报表显示算法版本，并保留新旧结果对比一段时间。

### 风险五：备份恢复尚需验收

有备份文件不等于可以恢复。

建议：至少每月做一次恢复演练，并将备份放到另一台设备或对象存储。

### 风险六：外部接口会失败

旺店通接口曾出现频率超限和连接中断。

建议：增加自动重试和失败通知，不要依赖人工第二天发现。

## 17. 最终结论

这套系统已经能够把旺店通数据转成可使用的库存、销售、采购、调拨和清仓分析，并能够生成较完整的日报和周报。

当前可以继续使用，但交接完成前必须重点确认：

1. 正式数据到底来自哪台服务器；
2. 每日 01:10 自动同步和日报是否持续成功；
3. 采购算法服务器实际运行的是哪一版；
4. 数据库备份是否真的可以恢复；
5. 网页访问是否已经做好权限和安全限制。

业务人员使用系统时，应把它当作“有公式、有数据依据的决策助手”，而不是替代旺店通、采购审批或人工判断的全自动系统。
